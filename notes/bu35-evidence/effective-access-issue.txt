Title: faccessat(AT_EACCESS): an effective-ids access query beside fs_access

At wolf 0.2.35 / lupin 0.1.56 / bundled std 2386522e, fs_access(path, mode)
EXISTS (wolf-lang#820, s254). The owned spec [os.fs.access] says it is
access(2), using REAL ids. It handles ACLs, immutable files, read-only
mounts (denied on EROFS), root's execute rule and the host's other access
rules. It returns () ! {denied, invalid, io, not_found, unsupported}.

The missing surface is EFFECTIVE access, requested but not added under R1
in [os.fs.gaps.note]. Ids are observable (wolf-lang#633 is the id-surface
reference), so boreutils can choose the real-id call when uid == euid and
gid == egid, which is every ordinary test. For set-id callers only, it
retains a mode-bit computation using effective ids/groups until the host
can answer this query. GNU test/euidaccess is the first consumer.

Requested surface: faccessat/faccessat2 with AT_EACCESS, or euidaccess and
the corresponding host operation on Darwin. Preserve the current mode
bits and rows, but ask with effective credentials. A boolean grant/denial
would also work if exceptional failures retain named rows and host errno.

Witnesses, only in an owned disposable Ubuntu 24.04 container:
- root-owned mode-000 file; setfacl -m u:1000:r--; actor uid/euid 1000:
  GNU 9.11 test -r and boreutils both exit 0 (parity, no exception).
- read-only source bind; actor root with equal ids: GNU and boreutils
  test -w both exit 1 (parity, no exception).
- the ACL file with real uid/gid 1001 but effective uid/gid 1000: GNU
  test -r and boreutils' mode-bit fallback both exit 1, despite a real
  read (cat) succeeding under those same ids. GNU shares this limitation.
- the read-only bind with real uid/gid 1000 but effective uid/gid 0:
  GNU test -w and boreutils' fallback both exit 0. A non-truncating
  O_WRONLY open, with no bytes written, fails EROFS. GNU shares this too.

These are measured shared limitations, NOT invented GNU-vs-boreutils
NOT-YET rows. The amended R-bu35-6 keeps compatibility and publishes the
witnesses; the predicates have no remaining access parity exception.

Reproducer: tests/identity-terminal/access-not-yet.py. The positive
2-argument witness is tests/identity-terminal/access-real/main.lu.
The requested third-argument shape in tests/gaps/bu35/effective-access/
main.lu gives E0402 (takes 2 arguments, not 3): this is an ARITY witness,
not an absent-name claim. [os.fs.access] is the authority for the missing
effective-id variant. R-bu35-6 amended accordingly; ordinary ACL/read-only
exceptions retired. No host ids or host-owned files are changed by a test.
